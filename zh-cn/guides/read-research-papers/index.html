一个完整的阅读流程

读懂研究文章，接住原来的思路。

以 HTML 研究文章为例，从一个不熟悉的词句出发，再回到作者的论证。

本页内容

  1. 先打开可阅读的 HTML 文章
  2. 每次选中一个理解上的障碍
  3. 看清上下文提供了什么
  4. 围绕尚未理解的问题深入一步
  5. 最后回到作者的论证

先打开可阅读的 HTML 文章

安装 API 版、配置自己的 DeepSeek 密钥，再打开 HTML 文章。如果发布方同时提供 HTML 和 PDF，请为这个流程选择 HTML：Explained 当前不在 PDF 阅读器内运行。

第一次可以使用体验区中的 DeepSeek-V4 短文。文中包含 KV cache，以及足以帮助理解问题的前后文。

  • 选择一篇体验文章
  • 安装 Chrome 扩展

每次选中一个理解上的障碍

先完整读一遍句子。划选不熟悉的术语，而不是整段文字，再点击划选图标，或按 Ctrl+X（Mac 为 ⌘X）。

在体验短文中，可以试试 KV cache。重点是理解它在这句话中的作用。附近上下文可以帮助模型解释当前语境中的含义，而不只是给出脱离文章的通用定义。

看清上下文提供了什么

展开回答卡片中的“使用的上下文”，与正在阅读的句子比较。开启附近上下文时，最多会随选区发送 600 个附近字符。

也可以从工具栏关闭附近上下文，再发起一次新查询，比较回答中哪些部分依赖文章内容。这是一种阅读练习；两次生成结果也可能因为其他原因而不同。

  • 看看同一个词在不同语境下的含义

围绕尚未理解的问题深入一步

简短解释仍有缺口时，可以点击 Explain a little more。v0.2.0 会重新进行网络搜索，并请求更详细的解释。依赖某项说法之前，先打开有关来源。

Keep it short 会返回缓存的简短回答。News 的用途不同：它搜索近期发展，适合追踪后续消息，不是对原句下定义的必要步骤。

最后回到作者的论证

  • 重新阅读原句，用自己的话说明它在文章中起什么作用。理解术语本身，并不等于证实论文结论。
  • 分清文中报告的测量、比较条件和自己的解释。条件与局限应回到原论文核对。
  • 把生成文字当作阅读辅助。重要事实、日期和引用，应与原始材料交叉检查。
  • 模型和搜索调用由你的 DeepSeek API 账户计费。需要连续阅读时，可以从工具栏暂停查询。
  • 排查阅读流程中的问题

设置完成，开始一篇好阅读。

打开体验文章，划选词句后点击图标，或按 Ctrl+X（Mac 为 ⌘X），开始第一次查询。
